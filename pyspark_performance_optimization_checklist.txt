1. CORE SPARK ARCHITECTURE FUNDamentals
================================================================================

[ ] Understand Spark Application Architecture
    - Driver program coordinates execution
    - Executor processes run tasks
    - Cluster manager (YARN, Mesos, Kubernetes, Standalone)
    - Task = unit of work on a partition
    - Stage = set of tasks that can be executed in parallel
    - Job = set of stages triggered by an action

[ ] Understand RDD vs DataFrame vs Dataset
    - RDD: Low-level, untyped, less optimized
    - DataFrame: Typed with schema, Catalyst optimizer
    - Dataset: Type-safe DataFrame (Scala/Java only)
    - Prefer DataFrames over RDDs for performance

[ ] Understand Lazy Evaluation
    - Transformations are lazy (map, filter, groupBy)
    - Actions trigger execution (collect, count, write)
    - DAG (Directed Acyclic Graph) built from transformations
    - Catalyst optimizer optimizes DAG before execution

[ ] Understand Lineage and Fault Tolerance
    - Lineage tracks transformation history
    - RDDs can be recomputed on failure
    - Checkpointing breaks lineage for long chains
    - Trade-off between recomputation and storage

[ ] Understand Execution Model
    - Narrow dependencies: data on same partition (map, filter)
    - Wide dependencies: require shuffle (groupByKey, reduceByKey)
    - Pipelining: narrow dependencies can be pipelined
    - Stage boundaries at wide dependencies


================================================================================
2. DATA PARTITIONING STRATEGIES
================================================================================

[ ] Understand Partitioning Basics
    - Partition = chunk of data processed by one task
    - Too few partitions: underutilized cluster, OOM
    - Too many partitions: overhead, small files problem
    - Target: 128MB-256MB per partition (HDFS block size)

[ ] Default Partitioning
    - Default partitions: spark.default.parallelism (RDDs)
    - Default partitions: spark.sql.shuffle.partitions (DataFrames, default 200)
    - Adjust based on data size and cluster resources

[ ] Repartition vs Coalesce
    - repartition(num): full shuffle, increases or decreases partitions
    - coalesce(num): no shuffle, only decreases partitions
    - Use coalesce when reducing partitions after filtering
    - Use repartition when need even distribution

[ ] Partitioning Strategies
    - Hash partitioning: default for most operations
    - Range partitioning: for ordered data
    - Custom partitioners: for specific distribution needs
    - Partition by column for joins/aggregations

[ ] Bucketing
    - Pre-shuffle data for frequent joins
    - df.write.bucketBy(numBuckets, "col").saveAsTable()
    - Reduces shuffle for subsequent joins
    - Works best for equality joins on bucketed columns

[ ] Partition Pruning
    - Partition data by frequently filtered columns
    - df.write.partitionBy("year", "month").parquet()
    - Spark reads only relevant partitions
    - Avoid too many small partitions (1000s of folders)

[ ] Salting for Skewed Data
    - Add random salt to keys for skewed joins
    - Explode skewed key into multiple keys
    - Join on salted key, then aggregate results
    - Reduces stragglers from data skew

[ ] Dynamic Partition Pruning
    - Spark 3.0+ feature
    - Prune partitions based on join conditions
    - Enabled by spark.sql.optimizer.dynamicPartitionPruning
    - Especially useful for star schema queries

3. MEMORY MANAGEMENT AND TUNING
================================================================================

[ ] Understand Spark Memory Model
    - On-heap memory: managed by JVM
    - Off-heap memory: managed by Spark (Tungsten)
    - Execution memory: shuffles, joins, sorts
    - Storage memory: caching/broadcasting
    - User memory: user data structures, UDFs

[ ] Memory Configuration
    - spark.executor.memory: total memory per executor
    - spark.memory.fraction: fraction for execution+storage (default 0.6)
    - spark.memory.storageFraction: fraction of execution+storage for storage (default 0.5)
    - spark.executor.memoryOverhead: off-heap memory for system overhead

[ ] Memory Tuning Guidelines
    - Leave 20-30% for OS and overhead
    - spark.memory.fraction: increase if OOM on shuffles
    - spark.memory.storageFraction: decrease if caching causes OOM
    - Monitor GC logs to tune

[ ] Garbage Collection Tuning
    - Use G1GC for large heaps (>4GB)
    - -XX:+UseG1GC -XX:MaxGCPauseMillis=200
    - Monitor GC time in Spark UI
    - Target: <10% of task time in GC

[ ] Off-Heap Memory
    - spark.memory.offHeap.enabled: enable off-heap
    - spark.memory.offHeap.size: off-heap memory size
    - Reduces JVM GC pressure
    - Used by Tungsten for binary format

[ ] Tungsten Memory Management
    - Binary in-memory format
    - Cache-aware computation
    - No Java object overhead
    - Enabled by default in Spark 2.0+

[ ] Spill to Disk
    - When memory insufficient, data spills to disk
    - spark.shuffle.spill: enable/disable spilling
    - spark.shuffle.spill.numElementsForceSpillThreshold
    - Monitor spill metrics in Spark UI

[ ] Memory Profiling
    - Use Spark UI Storage and Executors tabs
    - Check "Disk Spilled" and "Memory Spilled" metrics
    - Use -XX:+PrintGCDetails for GC analysis
    - Profile with Java Flight Recorder

4. SHUFFLE OPTIMIZATION
================================================================================

[ ] Understand Shuffle Operations
    - Wide dependencies trigger shuffle
    - Expensive: disk I/O, network I/O, serialization
    - Common shuffle ops: groupByKey, reduceByKey, join, distinct, reorder
    - Minimize shuffles in job logic

[ ] Reduce Shuffle Operations
    - Use reduceByKey over groupByKey (map-side combine)
    - Use aggregateByKey for complex aggregations
    - Filter before shuffle to reduce data volume
    - Combine multiple shuffles into one

[ ] Shuffle File Handling
    - spark.shuffle.file.buffer: buffer size for shuffle writes (default 32KB)
    - spark.shuffle.io.maxRetries: max retries for fetch failures
    - spark.shuffle.io.retryWait: wait between retries
    - spark.shuffle.service.enabled: enable external shuffle service

[ ] Shuffle Consolidation
    - spark.shuffle.consolidateFiles: consolidate shuffle files
    - Reduces number of open files
    - Important for large number of partitions
    - Enabled by default in Spark 1.6+

[ ] Shuffle Sort vs Hash
    - spark.shuffle.sort.bypassMergeThreshold: use hash shuffle for small reduces
    - Sort shuffle: default, better for large data
    - Tungsten-sort: optimized for primitive types
    - Auto-selected by Spark

[ ] Broadcast Hash Join
    - For small table joining large table
    - spark.sql.autoBroadcastJoinThreshold: max size for broadcast (default 10MB)
    - Set to -1 to disable, or higher to enable
    - Eliminates shuffle for small dimension tables

[ ] Shuffle Partition Count
    - spark.sql.shuffle.partitions: default 200
    - Too high: task overhead, small files
    - Too low: OOM, long tasks
    - Formula: total_data_size / target_partition_size (128MB)

[ ] Shuffle Read/Write Optimization
    - spark.sql.shuffle.partitions: adjust based on data
    - spark.shuffle.compress: compress shuffle data (default true)
    - spark.shuffle.spill.compress: compress spill data (default true)
    - Use LZ4 or ZSTD for faster compression

[ ] External Shuffle Service
    - spark.shuffle.service.enabled: enable external shuffle service
    - Allows executors to be removed without losing shuffle files
    - Required for dynamic allocation
    - Improves cluster utilization
